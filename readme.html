Quant Research Environment — README

Welcome. This folder is your sandbox for building, testing, and analyzing trading strategies. Read this once before you start, it’ll save you a lot of confused debugging later.

Folder structure

QUANT_ENV/
├── analysis/      # notebooks / scripts where you explore data, indicators, ideas
├── data/          # raw and processed price data (CSV files go here)
├── plots/         # output charts get saved here (auto-created by scripts)
├── strategies/    # one file per strategy idea — keep them separate, don't overwrite
├── backtester.py  # the core backtesting engine — don't edit this directly
└── readme.txt     # this file

How the workflow works

  1. Build your strategy logic in a script under strategies/. Your job is to generate a signal column: 1 = long, -1 = short, 0 = flat (you can also use fractional values like 0.5 for partial sizing — the engine scales position size by abs(signal)).

  2. Export a CSV with exactly three columns: datetime, close, signal. Save it to data/.

  3. Run the backtester on that CSV:

    python backtester.py data/your_signals.csv 10000 0.0003

    Arguments: <csv_file> [initial_capital] [transaction_cost_pct]. Capital and cost default to 10000 and 0.0003 (0.03% per side) if you don’t pass them.

  4. It prints a summary, and saves trades.csv and backtest_summary.txt in your current working directory — so run it from inside the strategy/data folder you’re working in, otherwise outputs will scatter wherever your terminal happens to be.

CSV format requirements (read this carefully)

  • datetime column must be in DD-MM-YYYY HH:MM format (e.g. 15-03-2024 09:15). Any other format will throw a parsing error.
  • close is your price series.
  • signal should not contain NaNs — drop or fill them before exporting, otherwise the engine will misinterpret a NaN != position transition as a trade.
  • Sort order doesn’t matter — the backtester sorts by datetime internally — but make sure there are no duplicate timestamps.

What the backtester actually does

  • Walks through your data bar by bar. Whenever signal changes value, it closes the existing position (if any) and opens a new one at that bar’s close price.
  • Position size = capital * abs(signal) — so a signal of 1 means you go fully long with all available capital, -1 means fully short, 0.5 means half capital long, etc. Signals above 1 in magnitude will use leverage (e.g. 2 = 2x your capital) — only do this intentionally.
  • Transaction costs are charged on both entry and exit, as a percentage of position value.
  • Any open position is force-closed at the last bar of your data so PnL is always fully realized.
  • Sharpe Ratio is calculated from daily returns (end-of-day equity), annualized with sqrt(252), assuming a 0% risk-free rate. If you’re used to a different convention, expect different numbers — that’s why, not a bug.

Common mistakes to avoid

  • Don’t compare Sharpe/CAGR across runs with different date ranges. If your data download has end_date=None (fetches “up to today”), running the same script on different days will silently use different data and give you different numbers. Always pin a fixed end date when reproducing results.
  • Don’t run the same script in two different Python environments and expect identical output unless you’ve checked both have the same package versions (pip freeze and compare, especially yfinance, pandas, numpy).
  • A high Sharpe with very few trades is not robust — check total_trades in the summary before getting excited about a number.
  • Always sanity check df.shape and date range after loading data, before trusting any backtest result downstream of it.

Getting help

If your numbers look wrong, before asking, check: 1. Does trades.csv have a sane number of trades? 2. Does your signal column actually look right (value_counts() it)? 3. Are you comparing two runs on identical data (same date range, same source)?

If all three check out and something still looks off, bring trades.csv + backtest_summary.txt + your strategy script when you ask.

Recommended packages & libraries

Install these in a dedicated virtual environment (venv or conda) — don’t install globally, and make sure everyone in the group uses the same versions to avoid the “different results in different environments” problem.

pip install -r requirements.txt

Data handling & numerical computing

  • pandas — core dataframe library, you’ll live in this
  • numpy — array math, underlies almost everything else
  • scipy — stats, optimization, signal processing
  • polars — faster alternative to pandas for large datasets

Market data

  • yfinance — free historical price data (what you’re using now)
  • ccxt — unified API for 100+ crypto exchanges, useful if you go beyond equities
  • nsepy / nsetools — NSE (India) specific data if relevant to you

Backtesting frameworks (for when you outgrow the custom script)

  • backtrader — popular, flexible, event-driven backtesting engine
  • vectorbt — vectorized backtesting, very fast for parameter sweeps
  • zipline-reloaded — maintained fork of Quantopian’s old engine
  • bt — lightweight, good for portfolio-level backtests

Technical analysis / indicators

  • ta — pure-python technical analysis indicators
  • ta-lib — the industry-standard TA library (C-based, faster, slightly annoying to install)
  • pandas-ta — pandas-native indicator library, easy to extend

Statistics & econometrics

  • statsmodels — regressions, time series models (ARIMA, GARCH via extensions), hypothesis testing
  • arch — volatility modeling (GARCH family)
  • pmdarima — auto-ARIMA model selection

Machine learning

  • scikit-learn — classical ML: regression, classification, clustering, model selection
  • xgboost — gradient boosted trees, strong baseline for tabular/financial data
  • lightgbm — faster gradient boosting, good for large datasets
  • catboost — gradient boosting with strong categorical feature handling

Deep learning (only if/when you need it)

  • torch (PyTorch) — most common deep learning framework in research
  • tensorflow — alternative, more production-oriented

Portfolio & risk

  • pyfolio-reloaded — performance and risk analytics, tear sheets
  • empyrical-reloaded — standalone risk/return metric calculations (Sharpe, Sortino, drawdown, etc. — useful for sanity-checking your own backtester’s math)
  • quantstats — quick, visual portfolio performance reports
  • riskfolio-lib — portfolio optimization (mean-variance, risk parity, etc.)
  • PyPortfolioOpt — simpler portfolio optimization library

Visualization

  • matplotlib — base plotting library
  • plotly — interactive charts (what your current backtester uses)
  • seaborn — statistical visualization, nicer defaults than matplotlib

Workflow & utilities

  • jupyterlab — notebook environment for exploratory analysis
  • tqdm — progress bars for long-running loops (parameter sweeps, etc.)
  • joblib — easy parallelization, also used for model serialization
  • python-dotenv — manage API keys/secrets without hardcoding them
  • requests — for hitting any REST APIs (data vendors, brokers)

Optional but worth knowing exist

  • numba — JIT-compile Python loops for speed, useful once vectorization isn’t enough
  • optuna — hyperparameter / strategy parameter optimization, smarter than grid search
  • pyarrow — fast file I/O (parquet), much better than CSV for large datasets long-term
